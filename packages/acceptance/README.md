# Bili-Bill 开发验收工具

独立于知识库 MCP 的开发工具。CLI 与 stdio MCP 共用同一客户端、本机管道、固定计划和扩展执行引擎。普通发行包不包含此入口。

## 使用顺序

1. 审阅新包 `Guide.html` 的确切视频、分 P、材料与预算，再批准用户级本地主机安装。`install.ps1` 不带 `-Apply` 只预览。确认后用 `install.ps1 -Apply`；卸载注册用 `install.ps1 -Uninstall -Apply`，计量和报告保留。
2. 加载新包 `extension/`，在扩展自己的设置中配置模型。固定开发扩展身份允许后续原位升级保留数据；不要卸载、清空数据或复制其他浏览器的配置。主机拒绝另一个浏览器档案重置计数；Chrome/Edge只能选一个作为收费执行实例。
3. 打开计划中每个视频的指定分 P，**手动开启原声 AI 字幕**。每个目标只留一个匹配标签页。图片样本为批准后执行采集时的当前画面，不主动 seek；为复现保留实际时间和图片摘要。
4. 从扩展弹窗进入“自动验收（开发）”，审阅完整计划和已知旧用量。勾选自动续接后，首次批准授予最长24小时的同计划任务，每次会话30分钟；关闭、刷新页面无需重新批准或更换配对码。未勾选时保持原30分钟页面会话。撤销、配置变化、任务到期、扩展重载、浏览器退出或主机断连停止授权；任务权限只在内存中存在，重启不会恢复。重新打开验收页可查看状态或撤销。
5. CLI：`node cli.mjs run-plan --extension-id <包内ID> --code <本次配对码> --output <明确的报告目录>`。完成自动冻结、串行生成、程序检查与本地报告。原始输出可由 Codex 用 MCP 分页读取、审阅评分及再次导出，不需要用户手工复制 JSON。
6. MCP：命令 `node`，参数 `server.mjs --extension-id <ID> --code <配对码> --output <报告目录>`。只有有限工具：状态、续接、冻结、单步生成、分段报告、评分、停止、报告导出；无批准新计划、任意JS/文件/密钥接口。CLI/MCP在发送新命令前自动续接临近到期或已到期的会话；也可显式调用CLI `renew` 或MCP `acceptance_renew`。MCP设置是否可用需单独设备验证；CLI无需宿主安装。

连接使用Windows命名管道，无 HTTP 服务。Native Messaging使用4字节小端字节长度加UTF-8 JSON；MCP使用SDK的JSON-RPC stdio，两者不是一条管道。消息<=256KiB，报告每段<=12000字符，绑定完整报告SHA-256。配对码是本次任务能力令牌，不是模型凭据；任务到期或撤销失效，不写入磁盘。

续接复核原计划、构建、模型配置及独立收费账本，不延长24小时任务总期限、不新增材料或步骤、不清除暂停、不请求模型。空闲管道断开时，下一个命令可用同一码重新配对；已发送命令如果丢失响应，立即报错，不能自动重放。主机本身断开需要重新授权。停止当前操作与撤销整个任务是两个动作。已运行到未知用量的计划可续接查看，仍不能执行未尝试步骤。

每个步骤最多一次请求；重复运行返回已有尝试，失败不重试。字幕优化是计划中指定的**一个**生产批次（最多32行/约4000字符），不是整部长字幕质量验收。新回测须新计划版本，历史和累计用量保留。扩展与主机各持久化收费占位，主机拒绝更换档案、账本回滚和超预算新增占位。断连后不自动恢复生成。

可复现模型回归的新计划用 `reuseFrom` 指定旧计划完整SHA-256，复用原字幕和原帧，生成前校验摘要。无需重新打开视频/开启字幕；改变视频或分P会拒绝。只有新增页面采集计划需要第3步。每个新计划仍固定新增调用数并累计计费；已有明确授权覆盖同范围回测时，不重复询问付费许可。

旧评测仍为总48次上限。真实验收已知旧32次/58,493 token作为计量基底，累计最多10,000,000。每次按输入和输出先预留100,000至200,000，未知用量暂停；这不是供应商计费保证。旧批次若有额外调用，先核对新完整账本；不能勾选已过时的确认项。其他扩展不并行评测。

2026-10-06用户已批准本次安装、首次配对、选定两视频的真实验收及必要修复回测，直到测试完成或累计10,000,000 token上限。此授权覆盖同范围内的新回测计划，无需再次询问付费许可；每份计划仍记录确切材料、操作与调用数，并在开发页建立可撤销会话。扩大视频/材料范围仍需授权，达到验收标准即停止。

2026-10-07用户要求先补自动续接与零模型费用页面回归。本源码已加入上述任务续接API。首次建立任务仍通过开发页；新计划、重启或撤销后不能用旧码新建权限。这是经过验证的源码能力，旧安装包不会因代码修改而自动获得它；原位升级可保留原账本，不需卸载扩展或重装主机注册。

## 零费用页面回归

设置已有测试运行时路径 `UX014_PLAYWRIGHT_MODULE`、`UX014_CHROME_EXECUTABLE`、`UX014_EDGE_EXECUTABLE`，运行 `npm run qa:acceptance:offline`。命令先构建生产文件，再在新建隔离Chrome/Edge中串行验证任务续接、字幕迟到/切换/跳转、分P身份、截图记录、草稿持久化、对话保存恢复和失效内容上下文。外部请求被拦截；模型响应、站点和原生主机按场景使用合成替身，不安装或调用真实主机，不读取个人浏览器数据。

每次输出独立的 `release-artifacts/acceptance-offline-pages-*/Report.html` 和JSON，绑定生产内容脚本SHA-256、各套报告SHA-256、两浏览器结果及失败日志。合成模型请求数量不计作真实调用；真实模型费用为零。该回归不能代表真实B站页面或模型质量验收。首次安装/新增权限仍是用户关键步骤。

报告明确区分mock、隔离安装但无网络、真实材料/模型、真实站点UI。当前工具不自动完成生产界面的分P操作、字幕开关、聊天保存恢复；这些保持“未验收”。后台获取/生成结果不能替代该测试线。无正文按生成失败处理。程序检查不替代关键事实核验；评分来自当前Codex，不声称人工团队或盲审。

仅有真实回答后才开展质量修复和新计划回测。材料和回答只写本地忽略目录，不自动上传；文档/Issue/PR仅包含无敏感数据的实现与验证摘要。

报告目录须预先创建。CLI/MCP在建立配对前验证它存在且可写；长材料计划可显式使用contextBytes=131072，报告同时记录输入大小和实际预留。该覆盖仅作用于验收计划，不改变日常对话的上下文设置。
