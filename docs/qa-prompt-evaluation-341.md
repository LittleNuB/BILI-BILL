# 固定样本提示词评测 #341

## 授权与边界

对应用户批准的真实效果评测，依赖 #340。只测试视频概览、多轮对话、字幕优化和图片解读四类预置能力；不覆盖自然语言改写提示词等其他能力。使用扩展当前配置的文字/图片模型，但比较的是两版**内置默认提示词**，不会读取、覆盖用户自定义提示词。

普通构建不引入评测页面或后台入口。开发验收包在已验证候选包副本上添加独立页面、静态 worker 模块和弹窗入口，原 manifest、版本、权限及旧验收包不变。没有 HTTP 远程控制服务、外部消息入口或任意提示词执行功能。

只有本扩展 `prompt-eval/index.html` 页面可连接专用 port。打开页面不发模型请求；“开始32次对照”是对固定合成数据批次的显式触发。首次运行要求文字模型和图片模型均已配置。扩展后台使用现有配置，不向页面或报告返回配置对象、密钥或鉴权头；不读取密钥文件、Cookie、profile、个人资料和知识库，不写正常会话/笔记/字幕缓存。

## 固定样本与旧版来源

`src/dev/prompt-eval/cases.ts` 冻结16例，每种能力4例；每例含输入、必须保留事实、禁止项、输出形式。4张 PNG 为自行绘制的确定性图表/代码/遮挡数字/错误提示，非真实视频截图。长材料包含92行受控文本；多轮对话历史为固定预置，不消耗额外模型调用。

基线为 #340 之前的 `8c7f3149b2063c483eca18266917b23d6b491aa1`。`scripts/freeze-prompt-eval.mjs` 从该提交读取实际提示词/构造器模块，用同一组固定材料生成完整 messages 快照；其余未变化的知识库和图片补充规则沿用生产逻辑。不是凭记忆重新写一套“旧版提示词”。

`tests/fixtures/prompt-eval/manifest.json` 绑定案例、输入构造器、图片、生成脚本、基线快照及原文件摘要。普通验证只比较，不重写。初次 `--freeze` 在清单存在时拒绝执行；不得为了通过修改事实标准。新样本需要另建版本，并保留旧数据。

## 真实调用与隔离

- 概览复用生产 `chatJson`、JSON 解析与摘要/亮点验证器；两组使用相同温度0.2和JSON模式。原始32次没有显式输出上限；经用户批准，续测显式使用所选上限，逐条记录参数，不改生产默认值。
- 字幕复用生产纠错格式和 `parseCorrection`；温度0.3、非流式、6000输出token。每例小于一个生产批次，不会隐含增加调用数。
- 对话复用生产历史构造、知识引用附加规则及 `streamLearningChat`；图片使用相同的实际图片附加协议、当前图片模型和供应商分支。对话流式偏好沿用当前配置，原始输出上限2048；续测默认8192，可选16384。知识库案例使用固定合成摘录，不进行真实本地检索。
- 对照只更换提示词；输入材料、历史、模型和参数相同。顺序交错，避免永远先跑旧版。记录完整messages、原始回答、解析值、SHA-256、请求模型、供应商实际返回模型、耗时和用量。未返回用量时记录null，不按字符伪造token数。当前流式协议若未返回usage，报告会保持null。
- 请求前持久化次数；串行执行。首批32次，显式补测最多16次，不提供清空重置按钮。失败、取消和中断均占位；刷新不重发，中断记录保留，用户可继续未运行项或待首批处理完后补测。鉴权/余额失败立即停止批次，缺失用量或用量超出预留也暂停；其他已知用量失败保留并继续后续案例；无自动重试。
- 页面关闭或模型/流式配置变化会取消活动请求。每次请求前重新检查配置；同一轮不能混入另一模型或参数。密钥变更可在停止后修复，但不导出或记录密钥本身。报告单独保存于扩展 `developerPromptEvaluationV1`，不与正常学习数据混用。
- 同一扩展、同一数据集升级评测构建时保留既有记录与48次计数；每次生成记录各自源码/构建和提示词摘要，不回写旧结果。不同数据集拒绝混入。新扩展身份不会自动迁移模型配置；本轮续测包可携带用户提供且已审阅的固定原始报告，保留计数及用量，不导入配置。

- 补测优先复查截断的连续追问与代码解释，再针对摘要重复、图表事实遗漏和矛盾结论修复。预算工具完成不代表提示词或真实模型效果已修复。

## 判断规则

程序检查和人工评分分离。格式检查覆盖JSON形状、证据行号、字幕id/顺序/多余字段、逐字重复摘要与亮点、错误知识库编号、把JSON或整篇代码围栏用作聊天回答等。不用正则推断所有语义正确性。

五项评分（正确性、来源诚实、任务完成度、可读性、简洁性）各0–2分；必须填写评分人和依据。单例只有请求成功、程序检查通过、事实与禁止项符合、无严重失败且总分>=8才通过。改动关键数字/否定关系、伪造引用、冒充看到图片等为严重失败，满分也不能抵消。所有实际回答先标“待评分”。`reviewed` 只表示已评分，不代表全部通过。

失败归为提示词、模型、接口/传输或解析；实际回答始终可查看和导出。报告包含失败和补测历史，不能只导出通过项。人工评分可修正，但不得修改测试输入或已保存的模型回答。对质量不足的修复必须按原案例再测，不能通过隐藏正文提升通过率。

## 评测页连接修复（2026-10-05）

用户报告页面“已断开”但仍一直显示“正在读取评测记录”。在独立 Chrome 安装原续测包后，首次打开正常，第二个评测页可确定性复现相同状态。根因是后台把只读连接也算作唯一 owner：旧页面仍连接时，新页面被 `EVAL_BUSY` 拒绝并断开；前端断开提示覆盖原错误，同时缺失加载失败状态。刷新也可能触发旧连接与新连接的交接竞争。不是模型生成慢，界面的零用量也不代表原记录被清除。

- 多个严格匹配本扩展评测页面的 port 共用一次初始化和同一引擎；只读连接不抢运行权，不恢复或自动重发模型调用。
- 修改、评分及生成使用同一个运行锁；并发生成被拒绝，不增加记录和收费次数。关闭只读页面不取消其他页面发起的生成；关闭发起页面仍取消其请求。
- 加载错误和断开均结束读取状态，保留准确错误及已读取记录；12秒无响应时显示连接超时，提供“重新连接”。未加载的计数、用量和配置显示“未读取/待确认”，不伪装成新批次零用量。未连接模型时禁用生成，但已保存回答仍可导出。
- 新增 `tests/prompt-evaluation.extension-qa.mjs <续测包extension>`：使用隔离目录在真实 Chrome/Edge 中加载最终开发扩展，网络阻断，无个人浏览器状态或真实模型调用；检查32条原记录、58,493用量、第二页面、刷新、导出、后台 stop/wake 和手动重连。`--source` 仅在本地副本重编译修复以作回归，不覆盖原验收包。
- 模拟浏览器回归另覆盖运行时加入读者、并发补测拒绝、关闭读者不取消任务、历史冲突提示及修复后重连。真实安装测试补上旧测试只模拟消息桥的缺口。
