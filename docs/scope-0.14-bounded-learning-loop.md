## 1. 裁决与合同优先级

0.14.0 首先交付：看视频时保存内容，关闭页面后能够找回，核对原出处，并能备份、恢复自己的整理。首版不承诺长期归档全部视频字幕或覆盖整个平台的字幕分布。

范围 PR 合并后，有限版合同顺序为：`AGENTS.md` 的安全与协作边界、本文件、有限版实现切片中冻结的技术合同。旧验收、PRD、领域定义、存储/迁移/备份合同及 ADR 中涉及下列冲突的部分只适用于后续完整知识库路线：

- 500 MiB 完整文本、64 MiB 单版本、全局视频正文索引及其 Gate-first 依赖。
- 保存知识自动提升整份字幕为受管全文，或字幕更新后保留完整历史版本。
- 将“智能收藏”替换为三视图知识库、同步多账号来源和稍后再看。
- 既有 backup v1 流式 ZIP、完整/轻量两种包及大规模恢复暂存协议。
- 首版必须通过旧 #242-#253 的全部范围，或将跨视频 AI 固定承诺在紧接的 0.14.1。

未冲突的隐私、来源真实性、数据不丢失、显式操作和回归要求继续有效。旧文档不是有限版缺失字段的默认补全来源。LG-0 必须先冻结有限版所需字段，不能直接照搬旧表拓扑。

旧 A2/C/D/E 结论与阈值原样保留。A2 未通过仍是证据不足；有限版免于该入口依赖是产品范围改变，不是 A2 通过或性能门槛放宽。旧 #239/#240 不因此获准派发。

旧开发计划 `development-plan-0.14.md`、Gate 合同 `architecture/gate-contract-0.14-storage-search-and-backup.md` 和 QA 矩阵 `qa-0.14-integration-matrix.md` 属于 B1 收据的哈希绑定输入，必须保留原字节。它们不内嵌新通知；改由 `AGENTS.md` 的发布范围规则、本文以及未被绑定的验收/PRD/领域/架构入口声明优先级。读到旧文件中的“必须先通过 Gate”或旧完成定义时，先区分有限版与原完整路线；不得重写旧收据来隐藏范围变更。

## 2. 首版保留的体验

| 动作 | 首版范围 | 必须可观察的结果 |
| --- | --- | --- |
| 观看与理解 | 复用当前视频字幕查看、检索、摘要、亮点及问答；不增加自动 AI 请求 | 不要求先同步收藏或采集字幕语料 |
| 保存 | 个人笔记、时间书签、字幕摘录、已验证摘要/亮点/回答；生成结果需用户明确保存 | 保存成功后刷新、关闭、重开仍存在；重复点击不产生重复条目 |
| 整理 | 编辑个人标题、笔记与标签，删除单条 | 用户层可改；保存的原文、回答及来源快照不可被编辑覆盖 |
| 找回 | 在独立“学习笔记”入口中搜索已保存内容、个人备注、标签和关联视频标题 | 说明命中的是个人笔记、已保存内容或视频信息；可按类型/视频筛选 |
| 核对 | 查看保存时的原文、精确分 P 与时间；预览、确认跳转、返回 | 视频失效时内容仍可阅读；不能伪造当前有效引用 |
| 带走 | 一个小型本地知识备份格式及非破坏性恢复 | 恢复失败无部分结果，成功后可搜索、核对；不含完整字幕缓存或账号配置 |

“学习笔记”是首版独立入口，不重命名或迁移现有智能收藏；旧路由、收藏同步、账单、动态账单和当前视频助手维持 0.13 行为。它是工作视图而非营销页面。

当前视频助手的功能、授权及证据语义维持不变，但表示层须完成 UX-014：收起态保留短视频标题、分 P、展开入口，有当前有效摘要时固定最多三行，无摘要时不显示占位或任务进度；展开为覆盖页面的浮层，优先显示当前任务正文，合并重复状态与说明，减少卡片嵌套，并跟随宿主页明暗。这里的“维持 0.13 行为”不要求原布局原样保留。浏览器工具栏 popup 和全局 dashboard 不在本次瘦身范围内。

每项资产限一个视频及至多一个精确分 P，可保存同一分 P 内多个真实引用区间。纯笔记关联当前视频但可以无引用；时间书签保存真实位置而不声称拥有字幕证据。跨视频合并资产暂缓。首版不批量把历史问答、收藏或字幕缓存转成个人知识。

保存来源支持的内容时保留最小视频展示信息、精确分 P、捕获时的原句、时间区间和来源版本绑定。字幕选区必须能精确映射；答案保存只接受当前已验证结果，保存前重新核验绑定，不能猜测部分选区与多条引用的关系。无法精确关联的回答选区不提供保存动作，可显式保存整轮已验证回答。

原文与回答快照是历史记录，不自动成为新 AI 请求的证据。首版不把任何已保存笔记或回答重新送入模型。跳转只能在目标视频/分 P/时间仍可核对时确认；字幕变化或暂时不可取时说明“保存时的内容”与当前核验状态，不静默重绑、不覆盖旧内容。普通书签的时间位置可核对时不额外强求字幕。

## 3. 明确暂缓

- 受管完整字幕、全文历史版本、500 MiB 空间及全库视频正文检索。当前视频全文继续遵守原授权和临时缓存生命周期，保存摘录不提升整份字幕。
- 多账号收藏来源重构、稍后再看接入和既有收藏自动迁移；已有收藏功能不删除。
- 跨视频综合问答、多来源资产合并、云同步、本地转录、向量检索、顺句与双语翻译。
- 流式 ZIP、完整/轻量双格式以及近 500 MiB 的恢复暂存架构。

这些能力没有被宣布完成或永久删除。旧完整知识库路线与 A2/C/D/E 保持独立待办，后续何时恢复及版本号另行安排。跨视频 AI 不进入有限版的完成定义。

## 4. 候选容量与数据保护

以下是用于 LG-0 实测的保守工程候选，不是用户指定的硬数字，也不是已经验证的产品能力：

- 最多 1,000 项资产。
- 资产及其全部用户内容、来源展示信息、引用快照、关联记录的规范 UTF-8 序列化总量最多 10 MiB，即 10,485,760 bytes。
- 字节统计覆盖所有持久个人知识，不把引用或元数据藏在计数之外。物理 IndexedDB 开销、可重建搜索结构和临时缓存另测，不被描述为 10 MiB 以内的实际磁盘占用。
- 个人知识不自动淘汰。创建、编辑、导入均先检查操作后的完整数量/字节，恰好等于上限可提交，任何超限整体拒绝；旧内容仍可阅读、删除和导出。
- 并发检查与提交必须在同一个可证明的写入边界内。配额估算不能代替真正写入成功与回读；保存失败不丢编辑稿。
- 数据库升级只新增有限版所需表，不投影旧收藏、不改旧缓存或问答内容。未来扩容/升级必须无损迁移已保存资产。

LG-0 固定逻辑记录字段、稳定身份、规范字节计算、去重/冲突规则、schema 升级和备份格式后验证上述候选。必须报告实际环境和性能，不能借用 B1 的 500 MiB 收据替代有限版实测。若候选不能通过，则记录失败并回到本范围 PR/后续范围修订；不临时增加上限、不静默删条目或放宽阈值。

## 5. 检索与备份边界

检索仅针对第 4 节有界的已保存知识及最小来源信息。无需视频全文索引、远程 embedding 或 A2 语料；不得称为“全局视频正文搜索”。LG-0 可采用有界、离线的本地检索方案，记录最坏查询时读取的数据量、主线程时间和内存；任何扫描/重建必须受首版数量与字节上限限制，不沿用到数百 MiB 语料。

备份候选为一个版本化、未加密的 UTF-8 JSON 文件，不使用旧 ZIP backup v1 格式或伪装兼容。只含持久个人知识和核对它所需的来源快照，不含账号关系、历史、完整字幕缓存、普通问答历史、模型配置、密钥或本地路径。导出前说明范围和未加密性质。

LG-0 冻结唯一格式标识、版本号、字段白名单、规范序列化、引用完整性和导入冲突算法。文件读入前检查大小；允许的输入大小必须覆盖该候选知识上限加固定、受限的封套开销，具体值和解释器内存上界由 LG-0 冻结并测试。未知格式/版本、非法字段、超限、损坏或悬空引用均整体拒绝；不自动尝试旧 ZIP 格式。

恢复先在有界范围内完成格式、身份、引用、冲突和最终容量校验，再以事务或经过验证的原子方案提交。相同内容跳过，冲突保留本地并生成可重复识别的导入副本；重复导入不增加副本。禁止用整库覆盖简化恢复。读取/验证期间可取消；提交期间需明确短暂不可取消状态或证明取消能够回滚，不能显示已取消却仍写入。

若缓冲/事务方案不能通过近上限内存与中断验证，则有限版不能发布；可修复或明确提出更小容量，但不能省略恢复、隐瞒部分写入或顺手引入完整大库架构。

## 8. 有限版验收与不可取消的保护

LG-0 先提供合成数据的容量/故障证据；LG-5 对实际生产 UI 和存储再次执行。没有真实字幕样本也可开发该闭环；少量用户体验视频只验证行为，不形成平台代表性或长期留存结论。

2026-09-07 用户确认验收职责：LG-0 只验收隔离原型及合成数据，不能在禁止生产接入时要求先验生产重置或扩展生命周期。LG-1 验收生产升级、保存与重开；LG-2/LG-3 验收当前证据适配和回看；LG-4 验收生产备份、清空、普通重置保留知识及真实扩展中断恢复；LG-5 做上述保护和 UX-014 的整版回归。这些是后续发布必需项，不是删除或免验项。LG-0 的 1000 项/10 MiB、256 MiB 合计堆采样增长预算及现有时间目标不变；采样方式和证据质量必须明示，不宣称绝对峰值或 RSS。已有内存超额仍是失败，必须修复并重新验证后才可冻结合同、解锁 LG-1。

下列延迟数字是新有限版的 LG-0 **待验证目标**，不是用户已批准或已经实测通过的硬门槛，也不修改旧 B1 的标准。LG-0 在首次正式测量前固定：OS/CPU/内存、Node/Chrome stable 精确版本、测试构建与源码绑定、公开安全合成 seed、正常与长正文/多引用/中英文病态资产、计时边界、空闲与峰值堆测量方式。每个固定场景至少 3 次独立冷启动和 5 次连续暖运行，完整报告所有结果，不能只保留通过的重跑。场景仅覆盖本有限知识上限，不扩展为全平台或 500 MiB 矩阵。

适用范围：搜索计时从提交本地查询至可用结果；冷查询包括打开有限知识存储/必需索引，暖查询复用已打开状态。主线程工作目标只适用于用户 UI；进度/取消目标适用于导出、导入验证和可取消重建，不把浏览器进程启动计入任务进度。原子提交不能假称可取消，必须明确状态并验证失败/重启一致性。LG-0 以该固定范围验证性能候选并将被接受的有限标准写入技术合同，LG-5 才按其验收。候选未达到时记录结果并修复或提出显式范围修订，经审查接受后再冻结；不得将失败改为通过、临时移动计时起点，或带着未裁决的候选直接进入 LG-1。数据完整性、精确容量拒绝和隐私是不可延期的安全条件，不因性能裁决而放宽。

- 容量：空库、典型小库、1,000 项与 10 MiB 边界、超 1 项/1 byte、单条接近总上限、重字段/多引用、并发创建编辑、删除再保存、quota failure。
- 持久化：新增表升级失败回滚；已有 v13 全部表不变；保存/编辑/删除中断后无半条资产或孤儿引用；连续重开结果一致。
- 来源：无字幕的纯笔记/书签可保存；有来源的摘录/答案拒绝过期绑定；分 P 变化、字幕变化和视频不可用不覆盖历史内容；旧问答记录不自动提升。
