# Bili-Bill 使用指南

[返回首页](../README.md)

本指南对应开放本地知识库迭代候选（#316/#325，2026-10-04）。旧预发布包 `v0.13.0-alpha` 不是同一套功能；版本字段未随增量开发更新，不代表正式 V0.14 已发布。

## 安装与第一次使用

按[首页的源码构建步骤](../README.md#开始使用)生成 `dist`，在 Chrome / Edge 桌面版的扩展管理页开启开发者模式，加载该目录。源码 ZIP 不包含 `dist`。

1. 打开 B站视频页，展开页内浮层。首次呈现概览；字幕与对话是独立标签页。
2. 先试本地记录：点击播放器旁的纸笔，写下理解并保存。输入时不暂停播放；时间点与引用字幕固定在点击瞬间。草稿按视频和分 P 保存。
3. 在完整面板的“知识库”查看记录。一个视频一页，分 P 在来源里；“新建页面”可创建自由命名的个人页。账单与盲盒在“更多工具”。
4. 想使用 AI，再填写模型服务地址、模型名与 API Key，检查连接并开启所需授权。项目没有提供共享 Key 或免费推理额度。目录与 Agent 也不是记录的前提。

浏览已保存的内容、记录笔记、Wiki 归组与 Markdown 导出不需要调用 AI。同步 B站历史、收藏或获取字幕，需要对应页面和接口当时可访问；账号相关同步应在已登录 B站的同一浏览器中操作。

### 随时重新打开帮助

知识库工具栏的问号是“使用帮助”，已有记录时也能打开，关闭不会删除草稿。帮助中的“文字 AI”或“图片模型”会进入对应设置区域；从这里配置后点击“返回知识库”，可恢复刚才的页面与编辑草稿。草稿写入失败时会停留原处，不强行跳走。

保存提示可关闭，也可点击“查看已保存页面”。“已存浏览器”不代表目录已同步。图片模型的“检查模型连接”只发送一条文字测试消息，会产生少量用量；通过只代表接口有响应，不代表已验证看图能力，也不会自动启用图片解读或学习资料授权。

## 字幕与回答

- 概览和字幕是独立页面；在底部输入问题并主动发送才进入对话。概览与聊天不会因切页或恢复会话自动生成；已主动启用的字幕纠错按当前视频偏好运行。
- 视频打开时自动获取可用字幕；如果没有，先在 B站播放器开启中文 / AI 字幕，助手会自动接收并采用，无需再检测或选择一次。手动选定的文本来源优先，换视频或分 P 不复用旧字幕。
- 默认优化阅读排版，不调用模型。AI 纠错需首次主动开启，之后记住偏好，只处理当前使用的视频。可切换原文、停止和继续未完成部分；时间轴不因纠错变化。纠错也可能有误，引用时仍可核对原文。
- 没有可用字幕时可以讨论一般知识，但不能据此声称总结了视频。标题、简介和常识不能替代视频原文。
- 预算允许时优先使用完整当前分 P 正文；长字幕的具体问题可以使用相关片段，全片问题采用分段覆盖。缺失或未覆盖的部分应明示，不能冒充全片总结。
- 长内容和接近预算的对话可能触发分段处理或摘要辅助请求，增加等待与模型费用；不承诺无限上下文。失败或中断后不会静默续发请求。
- 模型返回的可读文字可以展示，未核实与未完成状态仍会标注。可操作的引用只指向实际记录；引用存在也不等于观点一定正确。
- 字幕行与字幕搜索结果点击直接跳转，之后可返回；选中文字、搜索和切页不会自动跳转。AI 要点、模型引用时间点与外部视频仍先预览确认。保存按钮有独立条件，并非所有聊天回答都能保存为学习资产。
- 字幕支持搜索与 TXT / SRT 导出。首次保存笔记或截图时，留存当前分 P 已取得的完整字幕；单纯观看或收藏导入不触发全字幕入库。

## 图文笔记

- 相机入口点击即保存当前视频帧，之后补文字。时间点以实际捕获时刻为准。该帧重叠字幕与附近讲解分开显示；没有字幕也能保存。
- 视频截帧受限时，按提示点击浏览器工具栏里的 Bili-Bill，启用当前页截图后只保存播放器区域。授权前的时间点不会沿用到新的截图。
- 可以上传或粘贴 PNG、JPEG、WebP 图片，单张最多 10 MiB；图片独立存储，不嵌入旧笔记容量合同。
- 主动选择 AI 解读后进入现有多轮对话。先在设置中明确启用支持图片的模型；模型不支持时会提示失败，不能把文字回答当成模型已看图的证明。

## 目录与 Codex

1. 在知识库点击“连接目录”，选择已有笔记目录的父级或专用目录。只在其中的 `Bili-Bill` 子目录写入托管资料，不要求搬迁其他文件。
2. 等待状态变为“目录已同步”。“已存浏览器 · N 项待写入”表示浏览器已保留内容，但目录中还不完整。权限失效时重新连接同一个父目录。
3. 按[Codex 插件说明](../packages/codex-knowledge/README.md)构建/加载本地插件，配置 `Bili-Bill` 的绝对路径及 `library.json` 中的库 ID。需要 Node.js 24+。不要把整个用户目录配置成知识库。
4. 在 Codex 先检索并查看来源，再提出修改。个人正文必须先显示差异，通过宿主确认后应用；不支持 MCP 确认交互的宿主只能读取和提案。
5. 回到浏览器点击“刷新知识库”，或在未编辑时等待自动刷新。已确认写回不会二次询问。出现并发分支时，保留双方内容，打开合并编辑再保存。

历史按钮可查看旧版本；恢复创建一个新版本，不删除原历史。目录内的旧版本是不可变文件，直接覆盖它们会触发完整性错误，应通过编辑或提案更新。普通 Markdown 和图片仍可被其他工具读取。

“资料来源”中的外部 Markdown 选择器只授予读取。只读资料可在知识库搜索、引用；刷新时读取最新内容，撤销权限后不再用于检索。不扫描整盘。浏览器和 Codex 各自选择只读资料，不自动传递权限。另有“导入 Markdown 副本”是明确的复制动作，与只读连接不同。

## 收藏与提示词

在“资料来源”读取收藏夹，勾选本次要接入的夹，再“导入所选”。这是一次性导入，再导入才更新；“仅收藏资料”不代表已经学习或留下知识。平台删除、无权限和不完整导入都不会删除本地笔记。

提示词设置只保留一套当前配置，按概览、对话、字幕、图片分别编辑。自然语言改写先产生预览，应用后生效；可以撤销或恢复默认。改写提示词本身会调用已配置模型，但不读取整个知识库，也不能关闭引用、隐私和写回确认规则。

## 授权分别管理

| 授权 | 作用 | 默认行为 |
| --- | --- | --- |
| 当前视频 AI 助手 | 用当前分 P 可用文本辅助视频生成与学习对话 | 关闭；主动请求才发送 |
| 学习笔记用于 AI 问答 | 按当前问题在本地匹配保存内容，把相关节选交给模型 | 独立关闭；不因字幕授权自动启用 |
| 目标与偏好用于 AI | 让用户勾选的目标和回答偏好进入后续问题上下文 | 独立关闭；保存记忆与发送授权分开 |
| AI 字幕纠错 | 当前正在使用视频的字幕纠错 | 首次主动开启；可停止、撤销 |
| 图片解读 | 将明确选中的图片交给支持图片的模型 | 配置能力后仍需主动触发 |

知识检索最多取 6 个相关节选，引用内容合计不超过 8192 字节，并继续服从整体上下文预算。采用中文词项与有限同义词匹配；不保证找全所有相关笔记，不进行全库远程向量化。

目标偏好需要表单确认，不从普通聊天自动推断。最多 32 项，每项 512 UTF-8 字节，每次最多选用 6 项；实际使用还受预算限制。不要把密码、密钥或登录信息写进笔记或记忆。

删除、修改材料或撤回授权后，后续请求可能省略依赖旧内容的讨论及其摘要，原聊天记录仍留在本地。已发送给外部模型服务的内容无法由扩展收回。

## 更新与备份

**先备份，再更新；不要在唯一数据副本上做清空或恢复实验。** 本地保存不等于跨浏览器、跨设备或云端备份。

- 更新同一源码目录：拉取代码，重新执行 `npm ci` 与 `npm run build`，在扩展管理页重新加载，再刷新 B站页面。
- 换目录加载可能被浏览器视为另一份扩展。新扩展不自动继承旧数据，建议先禁用旧扩展，不要直接卸载。
- 新知识库右上角的备份图标可导出已保存页面、图片、原始资料、修改提案与历史。恢复先预览，再确认；只追加缺少的文件，保留并发分支，不覆盖本地版本。
- 新备份为未加密 JSON，最多 90 MiB 文件、64 MiB 解码资料与 20,000 个文件；合并恢复后的资料也不能超过 64 MiB。过大时不执行部分恢复，原内容保留。连接目录中的普通文件可另行备份。
- 新备份不含聊天、目标偏好、未保存草稿、外部只读文件、目录权限或模型配置。恢复后需重新连接目录；不能把知识备份当成整份浏览器数据备份。
- 旧记录通过增量迁移保留原身份、来源与主题，旧数据仍在“更多工具”的原学习模块中。后续页面正文在新知识库维护；旧记录不是开放页面的双向编辑副本。
- 视频页原有 Markdown 导出仍可用，内容来自已保存资产，不调用模型生成新正文。
- **旧格式**“学习与 Wiki 联合备份”仍包含旧学习资产、组织状态和主题。它不包含新图片或开放页面；恢复前必须预览，旧 Wiki 组织状态由备份替换。不要与新知识备份混用。
- 旧格式学习备份只恢复资产，不恢复或自动重建 Wiki 组织。普通打开视频不建 Wiki 页，真正主动新增保存才建立或重建该视频页。
- 新知识页使用归档，历史继续保留；旧视频 Wiki 的删除只适用于旧模块。
- 当前学习 / Wiki 备份不包含聊天、目标偏好或模型配置。**首版目标偏好没有导入 / 导出功能。** 请分别确认需要保留的内容，不把某一类备份当成整份浏览器数据备份。
- 删除聊天默认保留独立记忆；确认框中可以选择同时删除关联记忆。

原有个人数据的无损升级与异常恢复仍在正式验收范围内，不能由合成测试结果替代。

## 数据与能力边界

### 本地优先与模型服务

笔记、Wiki、会话、目标偏好与配置默认存放在当前浏览器本地。主动使用 AI 会向用户配置的服务发送完成该次请求所需的上下文；当前视频授权、知识授权和记忆授权分开。智能收藏等 AI 功能使用各自的元数据候选，不自动获得视频全文或私人笔记权限。

不整库上传历史、收藏、关注、反馈或笔记，不读取磁盘上的 Cookie、个人浏览器资料、B站登录态或外部密钥文件。扩展配置的 API Key 用于向用户选择的服务鉴权；界面不回显完整值。在共享浏览器中保存凭据仍有风险。

扩展不自动发布评论、点赞、投币或修改关注 / 收藏关系。动态账单的“少提醒这个 UP”只影响本地提醒，暂停 30 天，可撤销或恢复。

### 首版容量

| 内容 | 当前边界 |
| --- | --- |
| 旧学习资产 | 最多 1000 项，合计 10 MiB；旧正文上限没有扩充 |
| 旧 Wiki 组织 | 最多 4096 个页记录、128 个手动主题、8192 个关系，组织信息 2 MiB |
| 开放知识文件 | 单个页面版本 16 MiB，单个来源 32 MiB，单张图片 10 MiB；独立于旧正文 |
| 外部只读 Markdown | 明确选择至多 64 个，每个 2 MiB，文本总计 32 MiB |
| 目标与偏好 | 最多 32 项，每项 512 UTF-8 字节，总记录 32 KiB；每次最多选用 6 项 |
| 模型上下文 | 所有输入与输出余量共同受预算限制；没有无限长聊承诺 |

这些是实施边界，不是大规模真实负载已经通过验收的证明。达到容量限制时不应淘汰已有个人内容来腾空间。

### 观看统计与同步

- 本周从周一零点、本月从当月第一天零点算起，统计注明可用记录与覆盖日期。
- B站历史里的播放进度是跨设备估算，不能视为真实播放时长；本机 PC 时长来自扩展运行后的播放器心跳和播放事件。
- 同日同视频同时存在历史记录与本机事件时，优先使用本机实测避免重复计数。安装扩展之前的本机实测无法补回。
- 默认保留最近 90 天观看历史，暂不提供保留天数设置或无限归档承诺。本地历史可导出 JSON / CSV。
- 手动同步可选择最多 10、50、100 或 300 页，约 300、1500、3000 或 9000 条，实际返回由 B站接口决定。后台增量同步每 5 分钟检查，遇已有边界停止。
- 同一视频不同时间的观看记录会分别保留；同步锁避免重复点击造成并发写入，停止会取消后续请求与等待。
- 收藏同步维护当前可获取的快照，不写回 B站。收藏整理依据元数据，不下载视频或分析画面。

### 尚不提供

云同步、完整视频库自动抓取与全文综合问答、独立语音转录服务、连续画面分析、独立 OCR、说话人分离、自动跨视频综述、语义知识图谱或自主知识管理 Agent。

浏览器商店尚未上架。本轮验收见 [#325](https://github.com/LittleNuB/BILI-BILL/issues/325) 与[验证记录](qa-open-knowledge-integration.md)；旧 [#281](https://github.com/LittleNuB/BILI-BILL/issues/281) 和 A2 的结论不因本轮自动测试通过而改变。
