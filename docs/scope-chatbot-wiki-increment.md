# Chatbot 与 LLM Wiki 增量范围

日期：2026-09-09。范围 issue：[ #288](https://github.com/LittleNuB/BiliBili-DataViz-Plugin/issues/288)。

状态：用户已确认方向与推进顺序；本文件是 docs-only 范围变更，合并后供实施使用。文档完成不等于功能完成，不修改版本、tag、release，也不宣布 0.14.0 已完成。

## 1. 用户问题与当前基础

用户希望边看视频边连续追问、拓展知识，并用上自己的学习积累。当前逐题表单及显眼的会话管理打断学习；没有依据时整段拒答也不适合开放学习。

核对基线 main `c00bf338e8e83edb4751549d6ce70d6f7927c750`：已有多轮记录、学习笔记/摘录/回答快照、本地搜索、备份和浮层缩放。但问答请求只携带上一条通过校验且同文本身份的问答及最多 2000 字符滚动摘要；正文路径仍要求完整当前分 P 字幕。PR #287 在独立分支实现未核实正文可读，尚不能等同于开放学习、多轮 Chatbot 或 Wiki。

本方案复用这些基础，不搭建独立 Memory 服务、全字幕数据库或复杂知识图谱。

## 2. 合同优先级与不变边界

范围 PR 合并后，本文件只对 #289-#293 的新流程覆盖下列旧限制：

| 旧限制 | 本增量规则 |
| --- | --- |
| 回答只能来自当前视频正文，证据不足必须整段拒答 | 允许一般知识、模型分析与拓展，清楚区别于视频和个人材料；没有字幕不能编写该视频结论 |
| 请求只能包含完整当前分 P 正文，超长不分段 | 预算内优先全文；超长具体问题用相关片段和邻文，全片总结分段覆盖全文 |
| 保存的笔记/回答不得送入 AI，跨视频问答暂缓 | 单独显式启用知识 AI 后，仅发送与问题相关的有界保存内容，可跨视频比较这些材料 |
| 未核实模型正文不能保存为已验证学习证据 | 可明确作为模型生成内容整理到 Wiki，不能升级为视频原话或已核实来源；已有验证资产路径不被绕过 |

该覆盖不是对旧实现的完成声明。实现按各任务逐步替代冲突提示词、数据合同和测试；未改路径仍按原行为运行。不可为了切换范围重写历史证据或把原失败改成通过。

继续保留：本地数据无损、最小权限、不读取 Cookie/profile/登录态/凭据、不上传整库或无关笔记、不修改 B 站关系、用户触发 AI、来源可追溯、时间跳转预览/确认/返回。模型文本和 Wiki 内容是数据，不是可执行指令；不能借材料中的提示越过授权或触发操作。

来源内容不足不会阻止一般讨论，但实际来源、引用、时间点不能编造。输出正文展示与引用验证分离；未完成、未核实或来源不足只影响相应标记和动作，不静默藏掉已经返回的可读正文。

旧 #239/#240、A2 与 B1 收据不变；三个哈希绑定文档不修改。旧 #254-#257 属于完整知识库路线，不能直接派发或整体标为已完成。本增量不承诺全部视频正文留存、旧完整路线容量或独立 ASR provider。

## 3. 第一批可用聊天与浮层

- 连续用户/助手消息，固定底部输入；新建会话和历史入口简洁，重命名/删除放入菜单。保留当前会话草稿、滚动位置及中文输入法行为，不每题显示重复问题管理卡片。
- 请求真正包含近期完整问答。历史未核实正文仍可用于理解追问，但不是视频事实。普通追问不强制用户选模式，也不强制三段式答案。
- 流式显示、停止与重试；不支持流式的 provider 可正常返回一次性正文，不用逐字动画冒充网络流式。停止保留已显示文字并标明未完成；重试不重复创建用户消息或偷偷重发计费请求。
- 每条请求捕获来源身份。切换视频保留会话，但新问题用新当前视频；旧请求取消或完成时必须仍归属旧消息和旧来源，不重绑引用，不覆盖新上下文。
- 标题栏拖动与八方向缩放共存；按钮、输入、正文选择不触发拖动。收起态区分点击与拖动，维持已约定的信息展示，不加任务进度。
- 记住位置与尺寸，窗口变化时限制在可见区域，提供恢复默认位置；键盘与窄屏可用。拖动不重建聊天正文或丢输入。
- 首批建立可配置预算接口及超限保留问题的保护。自动压缩和长字幕覆盖在 CHAT-2 完成前不宣传已支持。

## 4. 长对话上下文

每次请求按预算组合：当前问题与指代所需原文、近期完整消息、早期会话摘要、所需视频文本、按需检索的个人知识、相关显式偏好。不是每次把所有层都装入请求。预算包含系统指令、所有输入及输出余量；模型窗口未知时用明确的保守配置，不假设所有兼容接口都有相同容量。

普通聊天不每轮额外调用模型做摘要。接近预算时，才对早期消息分段压缩并记录所覆盖的原始消息范围；保留原文用于查回。保存用户的纠正、已确认结论与待解决问题，区分讨论过/已决定/已完成。摘要不是事实来源，也不会自动写进 Wiki 或长期记忆。

摘要需要持久化，关闭面板或扩展后台重启后可恢复。摘要生成失败不删历史，任务中断不静默续发模型请求，删除后迟到写入不得复活记录。旧消息检索默认限本会话，不自动搜索所有私人聊天。

当前视频正文和历史共同受预算约束：全文放得下时优先保留完整理解；超长视频具体问题检索片段及邻文；全片问题分段覆盖、保存覆盖状态再综合。任何片段失败或遗漏必须明示，不把局部检索结果当成全片总结。模型拓展不用于填充缺失的视频证据。

用户触发聊天时可进行已告知的压缩/分段辅助请求，提供整体取消并限制工作量；打开、恢复、切换页面或开启设置本身不发 AI 请求。未知 provider 上限、额外请求成本和首字延迟需在实施中测量，不给出未经测试的无限长聊承诺。

## 5. 知识检索与 Wiki

知识分为原始学习材料、可编辑的 Wiki 整理层、会话层。用户笔记可以表达观点，模型整理可以包含拓展，但两者都不自动变为作者原话。

知识库 AI 使用独立的首次启用说明与开关，告知相关笔记发送到用户配置的服务；原字幕授权不自动覆盖。每次请求先本地有界检索、再发送相关片段，受条数、字节与上下文预算限制。普通追问不必查询 Wiki；未命中或检索失败不阻止一般知识讨论，但不能伪装用过未获取的材料。

答案引用能打开相应保存条目或 Wiki 页。来源时间与视频只取实际记录，失效来源仍可展示保存时内容，不伪造实时核验。撤回授权、删除知识或关闭功能后，新请求不能使用旧缓存；无法承诺收回此前已发送给服务的内容。

Wiki 第一版提供主题目录、主题/概念页、来源与相互链接。用户点击“整理到 Wiki”生成提议；预览新建/更新差异后确认提交。支持手工编辑、版本回看与撤销，原始材料不覆盖。不能每次只生成孤立摘要，也不自动批量改写全库。

提交须检查页面版本与来源状态，并发冲突不覆盖用户编辑；失败、取消、删除后迟到写入不产生半成品。Wiki 生成内容和原始引用分别标识，不能循环引用自身来证明模型结论已核实。Markdown 导出保留页面链接和来源说明；生成页面可再次供聊天检索。

Wiki 数据和版本会增加持久化范围。实施 PR 必须明确有限容量、删除、版本保留、备份格式及无损升级合同；不静默放大旧 1000 项/10 MiB 资产限额、不淘汰旧内容。现有备份没包含的数据不得声称已备份。技术参数在实现前写入对应任务，不能借本范围省略数据保护。

## 6. 显式长期记忆

长期记忆只保存用户明确要求记住的目标和偏好；提供查看、修改、删除、关闭入口。不自动推断画像、情绪或知识掌握程度，不保存凭据类秘密。首次启用告知选中的记忆会进入模型上下文。

会话摘要保存讨论进程，Wiki 保存整理成果，长期记忆保存明确偏好，避免重复存三份。删除聊天时说明是否保留关联的独立记忆，并支持同时删除；删除或关闭后新请求不再使用。记忆的容量与备份合同独立说明，不无限保存。

## 8. 风险匹配验证与完成定义

复用现有生产请求、会话存储、学习库、模型 mock 和浮层交互测试入口。日常改动只验证受影响行为，不为文案/CSS 重跑存储矩阵；多轮链路、知识写入及整版集成是集中复核节点。

关键外部行为：连续指代与早期细节查回；用户纠正后不沿用旧结论；未核实正文后可继续聊；停止/重试/迟到响应；视频切换来源隔离；长字幕覆盖与部分失败；后台重启恢复；拖动缩放保留输入；知识授权撤回与删除不复活；Wiki 冲突、撤销与备份恢复。

实现 PR 记录 focused tests、类型/构建、相关生产 UI 检查及实际限制；模型/真实站点未测不能由 mock PASS 替代。关键独立复核如需子代理使用用户指定 5.6 Terra / xhigh，不静默替换。
