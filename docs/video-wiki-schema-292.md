# 视频 Wiki 逻辑 Schema

2026-09-10。关联 [#292](https://github.com/LittleNuB/BILI-BILL/issues/292)、[#291](https://github.com/LittleNuB/BILI-BILL/issues/291)。基线 main `92e9a982eae52e6f10be2c7c70b81571a9eea262`。

状态：用户逐项确认的产品与逻辑数据合同；本 PR 只改文档，不创建表、不迁移数据、不实现功能、不更改发布版本。它收敛早期主题/概念页及模型整理提案，未定技术细节不伪装为已冻结 schema。

## 1. 页面与内容

- 一个 BV 对应一个视频 Wiki 页；分 P 作为页内分组，来源保留实际 CID、分 P 和时间，不猜测缺失分 P。
- 首次主动保存现有学习资产时建立页面；打开视频、浏览历史、后台扫描不建页、不触发模型。
- 视频整理：显示已经保存的摘要、要点。没有则留空，不从标题或模型常识补齐。
- 我的笔记：直接编辑现有笔记资产，与快速笔记、学习笔记列表共用同一份内容；原有并发编辑保护继续有效。
- 学习记录：关联摘录及已保存回答，不把聊天全部复制入库。分组是展示规则，不是新的内容副本。
- 原字幕入口保留全文与时间跳转，Wiki 不另存全字幕。引用定位到原资产和相关段落，不只给一个视频链接。

## 2. 逻辑对象

以下是字段职责，不要求对应独立物理表；物理结构和索引在实施 PR 定案。

| 对象 | 最小信息 | 不变量 |
| --- | --- | --- |
| 视频页 | BV 身份、最小视频展示信息、创建/更新时间、活动或已删除状态、并发修订标识 | 每 BV 至多一活动页；删除状态持久化，避免复活 |
| 现有学习资产 | 复用资产 ID、视频/分 P、个人内容、来源快照和实际时间 | 唯一内容来源；Wiki 不新增笔记正文副本，也不放宽既有保存校验 |
| 页内关联 | 视频页身份、资产 ID；分 P 和展示分区从资产获得 | 可通过查询派生；若物化须保持一致，不能生成不存在的资产引用 |
| 主题 | 稳定 ID、名称、名称是否已手动修改、并发修订标识 | 重命名不改变身份；算法不能覆盖手动名称 |
| 主题与视频关系 | 主题 ID、BV、自动关联或手动加入或手动排除 | 多对多；手动排除是需保留的负向决定，不是简单删除一条边 |
| 页面删除记录 | BV、删除时间及可拒绝旧写入的修订/代际信息 | 可与页面状态合并存储；后台旧任务不得凭旧资产重建 |

不新增独立 AI 整理正文或正文版本历史。用于并发控制的修订号不是用户可回看的正文历史，两者不得混淆。

## 3. 生命周期

| 事件 | 页面行为 | 原资产行为 |
| --- | --- | --- |
| 单纯观看/打开 | 不自动新建 | 不保存 |
| 首次主动成功保存新内容 | 建立该 BV 的页面 | 沿用原保存事务与来源校验 |
| 从任一入口编辑笔记 | 页面展示同一条更新后资产 | 单份更新，不互相复制 |
| 默认删除视频页 | 标为已删除，不参与可见主题聚合 | 保留笔记、摘录和回答 |
| 单独确认一并删除相关学习内容 | 删除页并按明确范围处理资产 | 必须有清楚预览与确认，不从默认删页推断授权 |
| 后台扫描、旧写入迟到或旧保存确认重试 | 已删除页不重建 | 幂等确认不等于新保存 |
| 删除后再次主动成功保存新内容 | 允许重建该 BV 页面 | 不把失败请求当成新内容 |

删除与保存并发须以实际提交顺序和代际检查处理，不能依靠墙钟时间猜测先后。一次操作失败不能报告整体成功；具体事务范围和重建时旧关联如何呈现，在实施合同中明确。是否恢复旧主题归属不得默认为用户已确认。

## 4. 主题聚合

- 本地算法按实际保存内容发现相关视频；标题只辅助匹配，不作为视频观点证据。
- 内容不足时不强行分类；主题可重叠，不要求每个视频只能归入一个目录。
- 自动分组允许用户重命名和调整归属；手动命名、加入及排除必须优先且持久化，算法不能改回。新视频仍可自动加入适当主题。
- 算法与相似度参数属于实现选择，尚未冻结；不引入远程 embedding、模型分类或自动上传全库。
- 不生成主题综述，不提供“生成整理”“更新整理”“整理到 Wiki”新增入口，不自动改写任何正文。原有显式摘要操作保持独立。

## 5. 聊天引用

#291 独立授权后，每次主动提问本地检索，有相关材料才带入请求。对应结论旁显示引用编号，点击在浮层查看标题、相关原文与来源，可打开完整条目；无匹配则继续一般讨论。

原始摘录、个人笔记、已保存模型回答和本次分析分开标识。知识库与当前视频冲突时并列说法及引用，解释可能的适用条件，不默认一方正确，不自动改笔记。主题关系不证明观点相同；页面组织层也不是独立事实来源。

Wiki 仅展示实际支持保存的资产。当前聊天中可读的混合模型回答若尚不符合资产保存合同，不因本方案而自动获得保存能力；该缺口必须明确跟踪，不能把模型回答悄悄改成原文摘录。

## 6. 实现前待定项

这些是需写入实施合同并验证的技术项，不是已确认新功能入口：

- 最终物理表、索引、唯一约束、迁移步骤；已有历史资产的首次接入方式，不能启动即绕过删页状态批量建页。
- 页面/主题/关系/删除记录的有限容量、写入失败和并发规则，不静默挤占或扩大原 1000 项/10 MiB 资产限额。
- 备份格式升级和旧包兼容；完整恢复需说明是否覆盖页面状态、主题名称、手动加入/排除及删除记录，不声称当前资产备份已覆盖这些新数据。
- Markdown 导出使用现有保存内容并保留来源；不调用模型，不顺带导出配置、凭据或完整字幕。
- 主题算法的增量计算、典型中文表达匹配及误分处理；没有真实效果证据不能宣称语义聚类准确。
- 删除后主动新保存重建时的旧关联/主题恢复策略；混合回答的新资产保存合同若要扩展，须单独明确，不混入组织 schema。

## 7. 验证范围

本次 docs-only：核对聊天决定、范围替换、链接及 diff；不重跑代码/存储性能矩阵，也不宣称生产验证通过。

实施阶段重点覆盖：同 BV 多分 P、资产跨入口编辑一致、首次保存建页、保存失败/幂等重试不误建页、默认删除保留资产、迟到任务不复活、主动新保存重建、手动主题决定不被覆盖、无额外模型调用、引用段落对应以及包含组织状态的备份恢复。
