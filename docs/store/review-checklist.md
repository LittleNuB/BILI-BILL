# 审核说明与素材清单

## 提交包

- 只从完成验证的 dist 生成 ZIP，根目录直接包含 manifest.json，不加 extension/ 外层目录。
- 不打包源码、测试 profile、收据、个人配置、密钥、截图原始资料或旧验收包。
- 包含随发行许可证；验证 manifest 版本与批准版本一致，并记录 commit 和每个文件的 SHA256。
- 在 Chrome 和 Edge 各自的干净测试环境安装并检查 MV3 后台；Edge mock 通过不等于两店安装通过。
- 截图和文案必须来自同一候选功能状态；尚未通过的真实模型流程不得写成已验证。

## 素材

按 2026-09-27 官方页面准备；实际上传时复核控制台规格。

- Chrome：128×128 PNG 图标、440×280 小宣传图、至少 1 张 1280×800 截图，计划 3 张。1400×560 大宣传图作为可选项。
- Edge：方形 logo 至少 128×128，推荐 300×300；计划复用 3 张 1280×800 截图。Edge 文档允许最多 6 张截图，另有可选宣传图。
- 三张截图主题：视频助手及连续提问、视频 Wiki 与出处、内容账单及本地管理。
- 使用实际运行界面，不用 imagegen 伪造功能截图。可以用明确标注的演示资料展示本地页面，不声称合成模型结果为真实回答。
- 公开图片必须脱敏，不包含用户头像、观看记录、浏览器其他标签、密钥或私人笔记；未经允许不使用用户之前上传的整屏截图。
- 当前既有 QA 截图仅为验证证据，不因存在就自动成为正式商店素材；仍须补齐规定尺寸、标注、权利检查和最终人工确认。

## 审核人员说明草案

1. 安装后打开工具栏 Bili-Bill，再进入学习笔记/视频 Wiki。无需配置模型即可验证本地整理入口；新安装没有自动导入的个人学习内容。
2. 在可访问的 B 站视频页展开助手，检查概览、字幕、对话；字幕可用性依赖视频和账号状态。不能取得字幕时，应呈现明确状态而非伪造内容。
3. 保存一条自拟测试笔记，打开 Wiki/学习笔记查找、编辑，重开验证；执行备份并核对恢复预览。只使用审核人员创建的测试资料。
4. 模型功能需审核人员自行配置兼容端点和自己的服务密钥，并开启对应功能授权。项目不提供公共密钥或替用户承担服务费用；如商店要求额外测试访问，单独确认安全的审核方案，不能在仓库提交凭据。
5. 主动发起两轮问题，检查视频与拓展知识标记、停止生成和历史记录；授权个人知识后检查引用预览。无配置或无网络时，检查明确失败状态，不将本地演示端点当正式可用服务。
6. 取消知识或记忆授权后，后续请求不应继续带入相应资料。默认删除 Wiki 页保留学习资产；不可把这个行为误判为彻底清空所有知识。

## 送审前仍需满足

#281 的待验项、发布者/账号确认、最终隐私政策、最小权限审查、最终截图与两浏览器安装、版本批准及提交预览。材料可提前准备，不能把“有 ZIP”或“有文案”标为已经上架。
