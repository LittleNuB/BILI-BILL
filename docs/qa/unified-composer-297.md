基线：main `bac41b0003fcf1ae54db8c56130b74e41cbd9199`。任务：[ #297](https://github.com/LittleNuB/BILI-BILL/issues/297)。用户已确认双状态视觉稿和下列交互，本任务同时包含实现及 QA；不代表发布或完整 0.14 验收完成。

## 已确认交互

- 顶部顺序为概览、字幕、对话。首次展开概览；当前视频/分 P 有已映射会话时，重新展开回到该会话。页面和会话恢复不触发模型调用。手动切页、输入与模式切换优先于迟到的恢复响应。
- 概览保留首句摘要，完整摘要及关键要点可展开；已有带真实时间的亮点合并为“视频要点”，先显示四项。现有生成合同没有完整章节分段，不能把这些亮点称作完整目录。缓存缺失时需显式生成，不能用标题填结论。
- 三页底部共用输入框，气泡+提问 / 纸笔+笔记可点击切换，悬停与无障碍名称说明目标模式。右侧纸飞机+发送 / 对勾+保存。发送后才进入对话，保存笔记留在当前页，保存成功后回到提问模式。
- 笔记模式进入时捕获时间位置，视频继续播放；空白可保存时间书签，有正文保存为带个人备注的时间书签，沿用旧资产格式、配额、搜索和备份。无可读时间不编造位置，播放器就绪后重新切入笔记可捕获。
- 字幕选区在输入框上方展示可移除引用，最多 32 条连续字幕、4000 字；首尾使用真实文本偏移，保存时后台重新校验来源和行绑定，保持原文与用户想法分层。原文字段因可见文案脱敏发生变化时不猜测偏移。来源失效不能偷偷变成普通个人笔记。
- 引用提问沿用原 500 字问题合同（引用和问题合计），超过时明确提示缩小选区，不静默截断；问答历史中保留完整引用文本，重试不会丢指代。来源选择不一致时先提示重新选择或移除，不绕过原字幕授权。
- 保留字幕全文、搜索、播放跟随、预览/确认/返回与导出；选择文字本身不触发播放跳转、保存或 AI。

## 数据与恢复边界

- 聊天草稿沿用本地最多 32 会话的旧规则。快速笔记草稿按视频/分 P 隔离，最多 16 份、每份输入最多 4000 字；只在当前页生命周期内保留，切页签/收起/SPA 跳转后返回可继续，完整刷新或关闭网页会丢未提交笔记，不宣传已自动保存。不会淘汰未提交笔记。
- 视频到会话映射在本地保留最近 32 项；它是路由偏好，不是原聊天数据，淘汰映射不删除会话。老会话无映射时可识别最近活动会话中同视频的来源，其他旧会话仍可从历史菜单手动打开。
- 快速保存保持既有两阶段捕获/来源复核/原子写入。请求失败后保留原稿与同一资产 ID/内容以确认重试，双击不重复提交；失效捕获只能以原固定时间/原选区重新核验。视频/分 P 不匹配则拒绝，不能重新绑定到新视频。
- 选区摘录的时间在来源快照引用中，普通时间书签的时间在原 bookmark 字段；不修改已冻结资产/备份格式，不扩大 1000 项/10 MiB 限额。
- 混合模型回答到笔记/Wiki 的新数据合同、知识库检索与长期记忆仍属 #291-#293。现有验证回答保存保持原边界，不把本次 UI 当作这些功能已实现。
- 首版不含 #296；2026-09-09 用户授权自主集成后，#296 合入 main `bbd85b0`，本 PR 已同步该基线并解决输入框冲突。提问模式保留发送前费用说明、整理阶段、整体停止及菜单中的原文定位；笔记模式不显示费用说明。未覆盖用户当前加载的候选扩展目录。
