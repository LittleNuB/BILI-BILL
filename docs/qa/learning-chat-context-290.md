# 长对话与超长字幕 #290

2026-09-09。基线 main `bac41b0003fcf1ae54db8c56130b74e41cbd9199`（#295）。本批为 #290 独立实现，不包含 #291-#293，不变更版本或历史 B1 合同。

## 有限实现合同

- 预算沿用 8192–131072，默认 32768；按完整 JSON 消息 UTF-8 字节作保守代理，预留 2048 输出和 1024 开销。它不是实际模型 tokenizer。普通/辅助请求都核算完整输入；已知 provider 窗口错误映射为中文可重试状态。
- 正文可容纳时优先全文。接近预算（85%）或历史被省略时才整理早期原文，每次至多 2 个分段；近期 4 轮优先，整理限定最近 8 条较早轮次。每份记录原始轮次和字符范围、原文摘要校验，不把模型整理当成事实。
- 最多保存 8 份整理，每份不超过 1600 字符/2400 JSON 字节；有界进度记录避免整理文本被淘汰后反复计费。旧正文不删除，重试修改旧轮次后失效的整理不进入请求。提问时可在本会话旧原文中本地查找相关节选，最多 2 条，不搜索其他会话。
- 超长具体问题使用本地词语匹配的字幕片段及邻文；未匹配时仅一般讨论。此路径明确未覆盖全文，不提供假时间引用。
- 全片问题通过关键词识别，或在已有全片处理中显式要求继续；确定性连续字符区间最多 24 段，每次最多 6 次段落处理。保存最近一次视频的覆盖状态，来源/内容/分段边界变更不复用旧结果。分段失败、仍有未处理段、超出 24 段及综合预算不足都不能声称完整覆盖。
- 全片整理使用依总预算及段数限定长度的模型摘要，再一次综合。即使所有段都处理成功，也只是覆盖全文的有损整理，不是逐字审计或事实核验；UI 和模型上下文都保留该说明。
- 单次发送最多 2 次历史整理 + 6 次视频整理 + 1 次回答。普通请求 90 秒上限，整次处理 240 秒整体取消上限。停止、配置/来源失效、会话清理共用 CHAT-1 的取消及写入守卫；打开/恢复/切换页面不触发 AI。中断仅在用户再次发送/重试时继续，不能后台续发计费请求。

## 保存与 UI

- 新增可选 `learningContext` 保存在原会话行，无独立表/版本迁移；旧会话无此字段仍可读，原文无损。整理和最近一份视频覆盖记录合计最多 64 KiB/会话，仍计入既有 25 MiB/200 会话容量与清理机制，不扩容。
- 生成失败不保存失败的模型整理；成功段保存后可在后台重启后恢复。完成/删除采用既有事务与代际写入守卫，删除后迟到整理不能复活会话。
- 现有学习资产备份不因此新增聊天上下文备份能力，不能宣称此字段已在资产导出中备份。派生整理的容量淘汰不删除原始聊天。
- 输入区及 AI 设置在发送前提示附加处理成本；生成中显示整理阶段，停止按钮保持可用。最终回答显示是否只用了片段、覆盖未完成或使用了早期整理。
- 会话菜单的“内容整理记录”可读生成整理并回到相应原始聊天；显示最近一次视频的分段记录，不冒称当前页面的视频字幕原文。

## 验证与限制

- 定向测试覆盖预算、无辅助请求的短聊天、字符连续分段、早期原文/纠正、失败与失效整理、重复计费保护、本地片段查找、完整覆盖/失败/上限、显式恢复及取消。生产 `askLearningChat` + 合成 IndexedDB/模型验证持久化重开、删除中止、窗口错误。
- 生产 content bundle + 合成宿主验证附加处理说明、阶段提示、整理记录/原文定位、片段说明、原多轮/草稿/拖动/停止及三种窄屏。截图与报告在本地 `release-artifacts/chatbot-290/`。
- 未使用用户真实模型、真实字幕样本或私人数据库；无法据此声明真实模型语义效果、成本或首字延迟达标。所有模型整理仍可能遗漏细节；词语匹配不是语义检索，超出有限分段范围应提高合适预算或缩小问题。
- 初轮全量 725/726；一项测试断言把“失败后不写空记录”的 `undefined` 当作失败，已修正为检查无摘要。最终测试/CI 和指定 Terra/xhigh 集中复核结果记录在 PR。
