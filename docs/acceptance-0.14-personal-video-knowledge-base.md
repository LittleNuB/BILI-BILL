# Bili-Bill 0.14 个人视频知识库验收合同

状态：本文保留完整知识库路线的验收合同。用户已采纳有限规模首版方向；[有限学习闭环范围](./scope-0.14-bounded-learning-loop.md) 在范围 PR 审查合并后优先定义 0.14.0 的发布范围、依赖与验收。本文件下文的完整知识库完成定义届时不再是有限版的发布条件，未冲突的安全与旧功能回归要求保留。本文件不授权修改版本号、发布、打 tag、合并 PR 或关闭 issue。

## 1. 合同顺序

发生冲突时按以下顺序处理：

1. `AGENTS.md` 的安全、文案、证据与协作规则。
2. 本验收合同的版本边界和完成定义。
3. `docs/PRD-0.14-personal-video-knowledge-base.md` 的产品合同。
4. `CONTEXT.md` 的领域术语。
5. 0.14 storage、backup、migration 和 gate architecture contracts。
6. 历史 PRD、原型或旧模块实现。

历史实现不能用于恢复已否决的产品逻辑。技术 gate 的真实失败证据可以把容量、检索或备份方案退回产品复核，但实现不得自行降低口径。

## 2. 发布顺序

- `0.14.0-alpha` 先交付个人知识基础：迁移、来源关系、知识资产、完整文本、本地检索、管理、备份与恢复。
- `0.14.1-alpha` 才交付跨视频知识问答。它依赖 0.14.0 的观察结果，不得与基础存储合成一个无法独立验收的大 PR。
- 全局正文检索、500-MiB 完整文本、流式 ZIP 与近上限恢复必须先通过 `gate-contract-0.14-storage-search-and-backup.md`。未通过时不创建对应运行时实现 PR。
- 本地语音转录、向量语义检索、Skill/MCP 自动触发、任意网页划词和云同步都不是 0.14.0/0.14.1 的发布依赖。

## 3. 0.14.0-alpha 完成定义

### 数据与迁移

- v13→v14 在一个 Dexie upgrade transaction 内完成；失败完整回滚并可重试。
- 只迁移可确定的旧收藏投影。不得迁移或推断稍后再看、知识资产、分 P、全文、当前账号归属或当前视频缓存。
- `favoriteFolders`、`favoriteItems`、`smartFavoriteIndex`、当前视频缓存、问答会话、历史、动态账单和设置内容保持不变。
- 旧收藏的重复 BVID、无文件夹、avid-only、非法数值和缺失元数据都通过固定 fixture 得到确定结果。

### 产品入口与来源

- Dashboard 顶层“智能收藏”替换为“知识库”，旧路由跳转到知识库的“收藏来源”。
- 知识库固定包含“已保存知识 / 视频资料 / 收藏来源”三类一级视图；空间管理是次级入口。
- 收藏和稍后再看是来源关系，不是个人知识，也不表示已看、未看或理解。
- 多账号来源只来自用户主动授权的当前浏览器运行态。任何账号切换、断开或完整同步都严格限定到对应本地账号与容器范围。

### 知识资产

- 支持纯笔记、时间书签、选区摘录和已保存回答四类资产；每项至少关联一个视频，纯笔记可以没有证据快照但不能是零视频关系。
- 支持从 Bili-Bill 已校验回答、摘要/亮点和 B站字幕视图保存；支持划词后的右键动作与较弱的整轮保存入口。
- 用户整理内容可编辑，保存内容和证据版本只读。重新定位来源必须选择、预览并确认真实视频、分 P、正文和时间范围。
- 多来源资产只保存一份所选内容，并为每个来源保留独立证据关系与版本。
- 创建、去重、编辑、重新定位和删除都具有原子性；失败不留下半个资产、孤儿关系或错误指针。

### 完整文本

- 0.14.0 只持久化用户知识空间内已取得正文的 B站字幕。同步不批量抓字幕，打开普通视频也不自动加入知识库。
- B站字幕仍需手动开启时显示“需要先在 B 站视频页开启字幕”，不谎称不存在。
- 同一视频、分 P、来源、语言和稳定轨道变体最多一个当前版本。无法稳定区分的同语言轨道只使用“默认 B站字幕”语义；正文或时间轴变化只形成待确认候选，确认后旧版成为历史版本。
- 恢复得到的正文可阅读和检索，但在真实来源核对前不能成为当前 AI 证据。
- 完整文本删除、容量管理和缓存清理不得删除知识资产或证据快照。
- 400 MiB 预警、恰好 500 MiB 可提交、超过 500 MiB 拒绝、账本修复和 64-MiB 单版本场景均通过 gate 与回读测试。

### 检索与导航

- 全局检索同时覆盖个人知识、可用完整文本和视频信息，并自然标明命中层。
- 基础检索不依赖 AI、向量或网络。搜索索引可删除和重建，不拥有唯一正文。
- 索引不可用时显示明确重建/失败状态，不扫描数百 MiB 正文，也不把标题检索冒充全局正文检索。
- 任何时间跳转都先预览、再确认、可返回；视频/分 P/来源变化使旧预览失效。

### 备份、恢复与清理

- 完整备份默认包含知识、证据和所有完整文本；轻量备份只包含知识与证据。两者都使用 backup v1 固定清单、字段投影、空值规则和记录顺序。
- 导出先获取用户选择的目标文件，再流式写 ZIP；不申请 `downloads` 权限，不构造近上限完整 Blob。
- 导出前说明可能包含个人笔记、保存内容和完整文本，并明确 ZIP 不加密。
- 恢复是非破坏合并：相同跳过、冲突保留本地并生成确定性导入版本、重复恢复幂等、本地当前全文不被备份覆盖。
- 畸形包、取消、配额不足、worker 中断或容量拒绝都不暴露部分恢复结果。信封级错误在暂存前拒绝，跨记录校验可使用不可见暂存；清理可续跑，重新尝试必须重新选文件。
- “重置 Bili-Bill（保留知识库）”保留个人知识与完整文本；“清空知识库”需要独立范围说明、输入确认和原子清理。

### 隐私与兼容

- 不读取 Cookie/profile/login-state/key 文件，不读取 `C:\Users\LittleNub\Desktop\Key.txt`。
- 不上传完整收藏、历史、关注、账号来源、知识库或备份；0.14.0 的新基础功能不自动调用 AI。
- 诊断、日志、UI 和公开 QA 证据不含正文、账号 ID、文件路径、密钥、raw runtime error 或内部字段。
- 当前视频助手、动态账单和视频盲盒保持 0.13 已验收行为；动态账单仍是兴趣再平衡，不是推荐排序。

## 4. 0.14.1-alpha 完成定义

- “知识库 AI”是独立、默认关闭的完整文本授权；开启本身、打开知识库或切换视图都不发送请求。
- 每次提问只选择一个本地证据范围：当前视频、个人知识空间或两者。范围由本地规则解析并对用户可见，不依赖 Skill/MCP 隐式路由。
- 一次请求最多五个精确视频/分 P 来源；每个选中来源发送完整主要文本，不只发送关键词片段，也不静默裁剪。
- 请求仅附带与问题直接相关的个人知识，并明确区分个人笔记与视频证据。
- 超过 512 KiB 的完整选中正文在发送前显示一次本轮规模、等待和费用提醒；用户取消则不发送。
- 模型回答先给自然中文结论，再列可核对来源；每个结论和引用都必须映射到选中来源的当前证据。
- 证据不足、某一引用无效、来源变化、服务拒绝上下文或请求取消均安全失败，不用元数据、旧回答、历史版本或通用知识补齐。
- 用户可以替换来源并重新提交；系统不静默改来源。有效多来源回答可显式保存成一项多来源知识资产。
- 0.14.1 不改变 B站关系、不做推荐排序、不自动生成全库摘要、不上传未选中的知识或账号信息。

## 5. 工程完成定义

- 每个 issue 使用 clean sibling worktree、`codex/` 分支和 draft PR to `main`；一个 issue 不混入 release/tag/package 修改。
- 每个 PR 运行 focused tests、`npm run typecheck`、`npm run build`、`git diff --check`、必要的 `npm audit --audit-level=high`、文案/raw 泄漏扫描和对应 Browser/mock QA。
- 所有 minified JavaScript chunk 小于 500,000 bytes；新增依赖有锁定版本、完整许可证、CSP/worker 资产和 release-dist 证明。
- 集成 QA 使用 clean integration worktree，逐项记录矩阵 ID 的 pass/fail/blocked 与证据。技术 PASS 不代表真实用户采用、长期留存或主观有用性。
- 独立子代理在首个运行时 issue 前和集成候选完成后各做一次第一性原理 code/docs review，按[复核策略](review-policy.md)选择可用模型并记录实际型号、源码与结果；must-fix 清零后才可进入人工体验。2026-10-19 用户取消对 Terra/xhigh 的型号限制。

## 6. 人工体验门槛

人工体验至少完成：从旧收藏进入知识库、创建/编辑/删除四类知识、保存字幕或回答选区、重访并找回、检索后回到原视频位置、完整/轻量备份、重复恢复冲突、全文空间状态，以及 0.14.1 的单视频和多视频问题。任何一次假跳转、证据错绑、重复恢复增殖、知识被清理、隐式上传或来源误归属都阻断版本接受。
