# 开放知识库整合验收

范围：#316 / #325。日期：2026-10-04。实现已进入可构建候选，**本报告不是正式发布、真实站点验收完成或旧 A2 通过的声明**。

## 本轮整合

- 浏览器聊天能检索同目录读回的 Codex 更新、页面正文、AI 补充、原始资料和明确选中的只读 Markdown。仅使用相关片段，引用可核对当前版本。
- 外部 Markdown 的选择、读取、重开、刷新、撤销和移除与“导入副本”分开。没有写入原文件的路径。
- 知识备份包含原文、优化版、图片、提案和版本图；先完整校验再预览，确认后追加恢复。已有内容与并发分支保留。
- 补齐清除与迁移竞争保护、旧保存入口写入目录、截图的分 P 来源隔离，以及 Markdown 内嵌图片显示。
- 显式重连增加独立连接代次：旧同步回执不能清除新目录的队列，正在编辑的草稿不失效。同一库的不完整目录也重放全部本地文件。
- 新验收包由 `npm run package:knowledge` 从干净提交构建，包含可加载扩展、Codex 插件、两份 ZIP、SHA-256、说明与独立验证记录。不会覆盖旧包或修改正式版本。

## 复现与短验收

先安装根依赖与 `packages/codex-knowledge` 依赖，使用 Node.js 24。为脚本设置 `UX014_PLAYWRIGHT_MODULE`（Playwright 模块的绝对路径）、`UX014_CHROME_EXECUTABLE` 和 `UX014_EDGE_EXECUTABLE`，在干净提交运行：

```powershell
npm run package:knowledge
```

该命令重新运行全量测试、两套构建、打包后的 stdio 测试和七组双浏览器流程，再生成唯一的新候选目录。运行失败保留失败报告，不产出通过声明。只使用测试上下文，不接入个人浏览器资料。

真人验收按[使用指南](user-guide.md)先备份，再检查：记录与截图 → 目录同步 → Codex 拒绝/确认修改 → 浏览器读回 → 冲突与历史 → 在空白测试环境恢复备份。不要为了演示清空唯一的私人数据副本。

实现可合并与整体验收完成是两个状态。#325 在上述真实边界验证前保持开放；#316 不标记完整交付。商店提交、正式版本、旧 A2 及 #281 单独处理。
