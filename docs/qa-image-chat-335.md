# 图片对话反馈修复（#335）

## 已确认的问题

- 非流式请求的鉴权、限流、服务异常、空正文及输出超限都落入“关闭流式输出”的通用提示。
- 图片请求的全部 400/415/422 被当作不支持图片，连明确的上下文超限也被遮蔽。
- 同一次失败同时出现在回答正文、重试说明、时间线及输入区。
- 笔记缩略图没有大图入口，对话只显示图片数量；重试旧问题可能使用输入区后来选中的附件。

## 本次修复

- 只使用有限错误分类展示中文提示，不展示服务原始错误、密钥或思考正文。思考内容仅判断是否存在，预算耗尽而无回答时单独说明。
- 普通参数错误不再断言模型没有视觉能力。非流式参数及用户选择的图片模型、图片字节由测试锁定。
- 失败只在对应轮次显示一次，重试沿用原轮图片；未成功建立轮次时在输入区提示并恢复问题。
- 笔记缩略图与聊天附件支持本地弹窗预览、关闭和 Escape，关闭后恢复焦点。预览不发送 AI 请求，也不下载外部图片。
- 来源及上下文说明收进“参考资料”；已持久化的失败问题不重新填回输入框制造第二份草稿。

## 验证

2026-10-04：新增四个回归先全部失败，再修复通过。定向用例覆盖图像载荷、非流式模式、错误分类、思考预算、图片来源隔离及重试附件绑定。

`tests/quick-images.browser-qa.mjs` 在 Chrome、Edge 使用生产内容脚本、真实 IndexedDB、合成视频及合成模型响应验证预览、单次错误、重试原图、记录保留和 1440/390 宽度。产物位于独立 `release-artifacts/quick-images-*` 目录。最终完整验证与打包记录以新候选包的 `verification.json` 为准。

## 未确认与边界

用户报告的真实 deepseek-flash 请求没有取得响应状态，因此不能确认实际失败原因，也不声称已验证真实图片识别。

[DeepSeek 图片文档](https://api-docs.deepseek.com/guides/vision/)明确支持 deepseek-flash 的用户消息图片块；[思考模式文档](https://api-docs.deepseek.com/guides/thinking_mode/)说明默认开启思考。当前聊天 2048 输出预算与默认思考的组合是待实测风险。

用户随后确认使用官方接口。本 PR 后续修复仅对官方 HTTPS 根地址或 `/v1` 的 Flash 图片请求明确发送 `thinking.type=disabled`，包括官方映射到 Flash 的两个旧视觉别名。此行为已经向用户说明，不更改保存的配置；不扩大预算、不自动重试、不影响普通文字请求、其他模型和第三方服务。新回归先失败再通过，验证流式及非流式均保留图片载荷与 2048 输出限制；不代表已复现用户实际服务端响应。

未读取用户密钥、Cookie、浏览器配置或登录态。旧验收包、发布版本和历史门禁不变。
