## 看过之后，还能留下什么？

教程看懂了一半，想追问一个例子；听到一句有用的话，想留下自己的理解；过一阵子遇到类似问题，又想找回当时的笔记和原句。

Bili-Bill 把这些动作接起来：**浏览器负责观看时的记录，本地知识库保留正文、图片和来源，Codex 负责在项目里取用、追溯并提出更新。** 资料是普通 Markdown 和图片，不要求搬空原有笔记目录，也不把知识锁在一个聊天窗口里。

| 当你需要 | Bili-Bill 帮你做什么 |
| --- | --- |
| 理解眼前的视频 | 看概览、读字幕、连续追问，也能讨论相关的拓展知识 |
| 留下自己的理解 | 播放器旁快速记笔记、保存当前帧，也可粘贴或上传图片 |
| 找回过去的积累 | 一视频一页，也有自由命名的个人页面；按主题关联，不自动写综述 |
| 把旧笔记用在项目上 | Codex 检索相关片段、追溯来源，展示修改差异并确认写回 |

## 边看边学

### 视频留在眼前，对话接得下去

浮层按 **概览 → 字幕 → 对话** 排列。首次打开先看紧凑概览；输入问题后进入对话，开始聊天后再次展开会回到原对话。标题栏可以拖动，边缘可以缩放，提问草稿跟着保留。

- **连续追问**：接着问“为什么”“举个例子”“和前面有什么区别”，不用每次重建背景。支持停止、重试和本地会话恢复；逐步显示取决于模型服务是否支持流式返回。
- **视频与拓展分清楚**：可以基于视频学习，也可以讨论一般知识。回答区分视频依据、个人材料与模型拓展；没有可靠字幕时，仍可一般讨论，但不会把标题或模型常识冒充视频结论。
- **原文没有藏起来**：字幕可查看、搜索，导出为 TXT / SRT；可定位的时间引用先预览、再确认跳转，并提供返回入口。
- **字幕自动接上**：可用时自动获取；在播放器开启字幕后自动接收，无需再选一次。默认整理排版；首次主动开启 AI 纠错后记住偏好，仅处理当前视频，原文与时间轴保留。
- **可读不等于已核实**：已返回的可读模型正文不会仅因引用校验失败被整段隐藏。未核实或未完成会标注，相应引用、跳转和保存动作仍需符合来源条件。

### 想问就问，想记就记

底部用不同的**提问图标**与**笔记图标**切换用途，两边各自保留草稿。选中字幕后可以带着这句话追问或记笔记；保存笔记不需要先发起 AI 请求，也不会把你带离当前页面。

播放器旁的纸笔入口固定点击时的时间与字幕，输入时继续播放。相机入口先保存截图，再补充文字；该帧字幕与附近讲解分开记录。直接截帧受限时，按提示从扩展工具栏授权当前页截图，只保留播放器区域。上传或粘贴图片后，主动选择解读才会发给支持图片的模型。

## 让积累再次派上用场

### 一条视频，一页 Wiki

主动保存学习内容后，视频会拥有自己的页面，分 P 与时间点保留在来源中。第一次保存笔记或截图时，同时留存该分 P 已获取的完整字幕；单纯观看不自动入库。原文、AI 优化版本和自己的笔记分开，不用模型改写原始资料。

知识库也支持自由命名的个人页面。主题只负责关联相关页面，不生成跨视频综述。收藏夹放在“资料来源”：选择后一次性导入，再次导入才更新；只含元数据的收藏与已有笔记区分，平台删除不会删除本地笔记。

### 与 Codex 共用一个本地目录

在工作台点击“连接目录”，新资料写入所选目录的 `Bili-Bill` 子目录。其他明确选定的 Markdown 只检索和引用，不修改原文件。未连接目录也能记录；界面区分“已存本地”和“已写入目录”。

[Codex 本地插件](packages/codex-knowledge/README.md)提供 Skill 与 stdio MCP：检索、读取、查看来源、新建个人页、提出修改和恢复历史。修改个人正文需要宿主展示差异并取得确认；浏览器读回后不重复询问。宿主不支持确认交互时，个人正文写回保持关闭。

目录内保留不可变版本，冲突保留双方，恢复历史会新建版本。直接编辑旧版本文件会被视为完整性异常；应通过浏览器编辑或 Agent 提案更新。其他工具可以直接读 Markdown 与图片。

### 回答能找到你记过的内容

单独开启“学习笔记用于 AI 问答”后，每次提问先在本地寻找相关材料，只把有限节选发给你配置的模型服务。引用出现在对应内容旁，点击 **[1]** 这样的编号，可以预览原文并打开完整条目。

引用会区分个人笔记、原始摘录与已保存模型内容。未找到相关材料时仍可继续讨论，但不会假装引用过知识库。跨视频比较针对你实际保存的材料，不等于读取所有视频全文。

### 只记住你明确确认的目标与偏好

例如“解释时先给一个小例子”。在设置中添加，或把一条自己的聊天消息带入确认表单，再决定是否记住、是否用于后续对话。可以查看、修改、删除或关闭；普通聊天不会自动生成个人画像。

长对话则由单独的上下文预算与早期对话摘要管理，原始会话保留供查回。它不会自动把聊天摘要写进 Wiki 或长期记忆，也不承诺无限长聊。

## 也看清自己的内容消费

学习之外，Bili-Bill 保留了个人内容账单的基础能力：

- **观看账单**：看本周、本月、连续观看时段与设备分布，同时显示实际数据覆盖范围。本机实测播放与 B站历史估算分开，不把历史进度当成准确时长。
- **收藏来源**：手动选择与导入收藏夹，不改动 B站原收藏夹；原智能收藏工具仍保留。
- **动态账单**：通过“被淹没的关注、收藏关联更新、关注轮换”帮助兴趣再平衡。入选理由和轮换由本地规则决定，不是“猜你喜欢”或点击率排序；少提醒某位 UP 只影响本地提醒。

## 开始使用

### 体验当前 main

需要 Git、Node.js **24（与本仓库 CI 一致）** 与 npm，以及 Chrome / Edge 桌面浏览器。

```bash
git clone https://github.com/LittleNuB/BILI-BILL.git
cd BILI-BILL
npm ci
npm run build
```

1. 打开 `chrome://extensions` 或 `edge://extensions`，开启开发者模式。
2. 选择“加载已解压的扩展程序”，加载项目里的 **`dist`** 目录。
3. 打开 B站视频页，先用纸笔记一条笔记，到完整面板的“知识库”查看；不必先配置 AI、目录或 Agent。
4. 需要与 Codex 共用资料时，再连接本地目录并按[插件说明](packages/codex-knowledge/README.md)构建与配置插件。
5. 使用 AI 时，配置模型并检查连接，开启所需授权。按功能编辑提示词，或用自然语言生成改写预览，确认后应用；支持撤销和恢复默认。

仅浏览与记录学习内容不需要 AI Key。视频相关生成还需要当前分 P 可用的字幕；[字幕未出现时怎么办](docs/user-guide.md#字幕与回答)。更新源码后需重新构建、重新加载扩展，并刷新视频页。

**旧用户先备份重要内容。** 换一个目录加载可能产生新的扩展身份，不会自动继承旧数据；不要直接卸载唯一的数据副本。详见[更新与备份](docs/user-guide.md#更新与备份)。

## 数据由你掌握

笔记、Wiki、会话和目标偏好默认保存在当前浏览器本地，**本地优先不等于 AI 完全离线**：

| 操作 | 发往你配置的 AI 服务的内容 |
| --- | --- |
| 看页面、记笔记、浏览或分组 Wiki | 不因此发起模型请求 |
| 主动请求视频相关生成或提问 | 授权范围内的当前问题、所需视频文本与有界会话上下文 |
| 启用学习笔记授权后主动提问 | 按问题匹配到的有限保存内容，不上传整库 |
| 启用目标偏好授权后主动提问 | 本次预算内使用的已勾选目标与偏好 |
| 主动开启字幕 AI 纠错 | 当前视频待处理字幕；可停止，保留原文与部分完成结果 |
| 主动解读图片 | 选中的图片与本次对话所需上下文；不支持图片的模型明确报错 |

智能收藏等 AI 功能使用各自的最小上下文，不继承视频全文授权。关闭授权会阻止后续使用，但无法撤回已发送给外部服务的内容。API Key 保存在本地配置中，不要在共享浏览器中保存不适合共享的凭据。

Bili-Bill 不读取磁盘上的 Cookie、浏览器资料或外部密钥文件，不自动取关，也不向 B站写回收藏或关注关系。[完整说明与容量边界](docs/user-guide.md#数据与能力边界)

## 当前进展与边界

**候选功能**：多轮学习、自动字幕与可取消纠错、图文快捷笔记、知识工作台与收藏来源、本地目录和版本冲突、Codex 提案写回、相关材料引用、图文备份恢复、提示词配置。参见[实现索引](docs/product-overview.md)。

**已验证与待验证分开**：双浏览器合成流程已覆盖读写、冲突、历史、图片和备份；真实 B站、真实模型、原生目录授权与当前 Codex 宿主尚未完成整体验收。[验收记录](docs/qa-open-knowledge-integration.md)

当前不提供云同步、连续视频画面分析、独立 OCR / 语音转录服务、全库视频问答、自动跨视频综述或自主知识管理 Agent。旧学习资产仍受 **1000 项 / 10 MiB** 约束，新图片与开放页面独立存储。新知识备份不含聊天、目标偏好、未保存草稿或模型配置。[容量与备份边界](docs/user-guide.md#更新与备份)
